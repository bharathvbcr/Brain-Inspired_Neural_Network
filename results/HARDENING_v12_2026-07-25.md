# Hardening v12 — 2026-07-25

Companion to `results/HARD_AUDIT_v12_2026-07-25.md`. Every defect in that audit is
addressed below, and each fix ships with a **regression guard** so the same class
of bug fails the build rather than reaching a report.

> **Not yet compiled.** The fixes were written without a Rust toolchain available.
> Run the commands in §4 before trusting anything here.

## 1. Fixes by defect

### 1.1 Constant predictors (`c1_enhanced`, `multi_area_scaling`)

**Root cause:** the sample was never fed into the network, and
`predicted = !winners.is_empty()` is constant by construction.

| File | Change |
|---|---|
| `binn-lab/experiments/c1_enhanced.rs` | New `present_stimulus()` injects a seeded projection of `sample.values` into the engine over `STIM_TICKS` and steps it; readout is a reward-modulated linear map over the k-WTA **winner identity**, not winner-set emptiness. Splits raised to 300/100. |
| `binn-lab/experiments/multi_area_scaling.rs` | New `encode_area0_winners()` derives area-0 activity from the sample. Dataset seed **fixed at 100** across all M (was `toy(100 + n_areas)`). Splits raised to 300/100. Feedback plasticity now uses real per-area activity via `winners_to_activity()` instead of `vec![1.0; n]`. |
| `binn-learn/src/multi_area_learn.rs` | `update_inter_area_feedback` no longer takes an unused `&mut weights`. New `update_inter_area_weights()` actually applies feedback-aligned forward plasticity — previously `B` was learned and nothing consumed it, so the forward pass was frozen. `find_row_for_edge` (O(nnz·nrows)) removed; both updates are O(nnz). |

**Guard:** `binn-lab/src/guards.rs`

- `StimulusProbe` fingerprints the pre-readout state per sample. Identical
  fingerprints across samples ⇒ `Degeneracy::StimulusNotDelivered`.
- `ReadoutAudit` reports accuracy, Wilson 95% CI, the constant-predictor
  baseline, distinct-prediction count and distinct-state count.
- `ReadoutAudit::assert_non_degenerate()` **panics** rather than writing a
  degenerate number into a report. Both experiments call it.
- `MIN_EVAL_SAMPLES = 50`; smaller eval sets return `Verdict::Underpowered`.

### 1.2 Hardcoded verdicts

| File | Change |
|---|---|
| `deep_snn_scaling.rs` | All four `PASS` literals removed; verdicts from `Verdict::evaluate_mean`. |
| `ei_inhibition_sweep.rs` | Per-row `PASS` literal removed; three falsifiable criteria added (see §1.5). |
| `multi_channel_neuromod.rs` | Both `PASS` literals removed; four falsifiable properties added. |
| `live_transfer_rescue.rs` | `FAIL` / `PASS (matched)` literals removed. |
| `track_b_rescue.rs` | Verdicts routed through `Verdict`. |

**Guard:** `binn-lab/tests/report_verdict_guard.rs` scans every
`binn-lab/experiments/*.rs`, splits markdown table rows in format strings on `|`,
and fails if any non-placeholder cell is a verdict literal. Two self-tests prove
the detector catches the original `deep_snn_scaling` row and does not
false-positive on computed verdicts. Opt out with `// verdict-literal-ok: <reason>`.

`Verdict` is constructible only from `(measurement, threshold, harness_valid)`,
so a verdict cell cannot contradict the number beside it. `Verdict::InvalidHarness`
and `Verdict::Degenerate` return `false` from `is_citable_as_positive()`.

### 1.3 Fake GPU benchmark

`binn-core/src/metal_backend.rs` rewritten:

- `use_gpu: bool` → `Backend { CpuParallel, MetalGpu }`.
- `METAL_GPU_DISPATCH_IMPLEMENTED` (currently `false`) is the single source of truth.
- `SpmvBackend::try_new` **refuses to construct** an unavailable backend; `new`
  panics. There is no path to a GPU-labelled handle that runs on the CPU.
- `SpmvBackend::label()` reports the substrate that actually executed.
- `benchmarkable_backends()` returns only available substrates, so a benchmark
  loop cannot emit a two-arm table whose arms are the same substrate.
- `MetalGpuContext` methods are `todo!()` with a documented implementation
  checklist. Flip one const when dispatch lands; the parity test activates itself.

**Guards:** `unimplemented_gpu_backend_is_unconstructible`,
`benchmarkable_backends_are_distinct_and_available`,
`labels_describe_the_executing_substrate`, and a gated
`metal_gpu_matches_cpu_reference`.

### 1.4 SHD ceiling crippled by modulator scale

The DFA arm used `B ~ U[−1,1]`; the e-prop ceiling transported through
`wout ~ U[−1,1]·0.2/√h`. At `h = 128` that is **56.6×** in effective hidden step
size at the shared `lr = 0.02` — the sole reason the "ceiling" (0.092–0.126)
scored below the treatment (0.209–0.239).

| Change | Where |
|---|---|
| `B` initialised at `shd_out_scale(hidden)`, identical to `wout` | `shd_eprop_baseline.rs` |
| e-prop transports through a **snapshot of `wout` taken before** the readout update | `shd_eprop_baseline.rs` |
| Both arms accumulate realised modulator RMS | `ShdDfa::modulator_scale`, `ShdEpropCeiling::modulator_scale` |
| Report emits a **Ceiling health** table + explicit warnings | `runner_shd_cal.rs` |
| Reproduce block always emits `--shd-hidden <n>` and the matching out path | `runner_shd_cal.rs` |

**Guards:** `dfa_feedback_and_readout_share_init_scale` (ratio < 1.5 at h ∈ {32,128,512}),
`dfa_and_eprop_modulator_scales_stay_comparable` (post-training RMS ratio ≤
`MODULATOR_PARITY_TOLERANCE = 3.0`), `eprop_transport_uses_pre_update_readout`.
The report additionally prints **CEILING INVERTED** whenever a ceiling arm scores
below the DFA treatment.

### 1.5 Missing depth-matched ceiling

New `binn-learn/src/matched_deep_gradient.rs`: `MatchedDeepGradient` over 1..N
hidden layers with a forward identical in structure to
`MatchedRlDeepLearnedFb` — same init scales, `α = exp(−1/τ_m)`, hard reset,
rate-coded inter-layer signal, rate readout. Credit is transported through the
forward weights, RMS-normalised per layer by default so the learning rate alone
sets step size (i.e. it does not repeat the SHD pathology).

`deep_snn_scaling.rs` now runs a ceiling **at each depth**, prints the realised
modulator RMS per depth, and flags any depth whose ceiling falls below its own
treatment.

**Guards:** `trains_at_every_depth_without_panicking`,
`raw_transport_collapses_deep_modulator_scale` (reproduces and detects the SHD
pathology), `modulator_scale_arithmetic`, `rms_normalise_is_scale_free`.

### 1.6 Gap-closed > 1.0

`guards::gap_closed_clamped(local, dense, reference, min_reference_gap)` clamps to
`[0, 1]` and returns `None` when the reference/dense separation is below the
preregistered `0.15` — matching the C1 runner, which always clamped.
`gap_closed_exceeds_ceiling()` reports the raw overflow as a **harness warning**.

`track_b_rescue` and `live_transfer_rescue` both use it, count the seeds that
exceeded the ceiling and the seeds excluded for insufficient separation, and set
`harness_valid = false` when any seed overflowed — which forces
`Verdict::InvalidHarness` and blocks a PASS.

**Guard:** `gap_closed_is_clamped_and_gated` asserts the shipped 1.0244 case
clamps to 1.0 and is flagged.

### 1.7 Non-experiments given falsifiable criteria

**`ei_inhibition_sweep`** — driven with heterogeneous sparse activity (10%
strongly driven), 10 seeds × 50 steps. Three criteria: C1 monotone in `W(I→E)`,
C2 monotone in E:I, C3 inhibition differential across cells. **C3 is expected to
FAIL**: `compute_inhibition` returns `vec![inhibition_per_e; n]` — one scalar
broadcast to every cell, which cannot reorder k-WTA winners. The report states
that this module provides divisive gain control, not competition.

**`multi_channel_neuromod`** — 20 seeds, four properties: P1 magnitude
monotonicity, P2 sign reversal, P3 ACh proximity gating, P4 per-cell
addressability (a broadcast scalar fails P4). Caveats state it is a property test
of the modulator, not a learning result.

### 1.8 Interpretation caveats now emitted by the code

`deep_snn_scaling` prints, in the report itself, that `CoincidenceTask` has
`N_IN = 2` and `difficulty = 0.05`, so a 256⁴ stack has no depth structure to
exploit and a depth result on this task is weak evidence either way.
`live_transfer_rescue` states that `1.0000 ± 0.0000` beating the BPTT reference
indicates task saturation rather than credit-assignment quality.


### What to look for in the smoke output

- `c1-enhanced` / `multi-area-scaling`: a panic with `readout arm ... is degenerate`
  means the stimulus path is still not reaching the readout — that is the guard
  working, not a flake. Investigate `INPUT_GAIN` / `STIM_TICKS` before disabling it.
- `deep-snn-scaling`: `Ceiling health` should read `ok`. `INVERTED` at any depth
  means the depth-matched ceiling still needs a learning-rate sweep.
- `ei-inhibition-sweep`: **C3 is expected to FAIL.** That is the correct result
  for a uniform-inhibition implementation.
- `shd-cal --quick`: check the new `Ceiling health` table. The RMS ratio should be
  well under 3.0; if `CEILING INVERTED` still appears, the remaining cause is
  learning-rate, not initialisation, and the arms need a per-arm LR sweep.

## 6. Deliberately not fixed

These are in the audit but are research decisions, not bugs:

1. **Move the matched-arch suites off `CoincidenceTask` (N_IN = 2).** The task is
   saturated; `1.0000 ± 0.0000` beating BPTT proves it. The code now says so in
   every affected report, but the suites still run on it. The SHD path exists and
   is the natural target.
2. **Shuffled-label control for the SHD arms.** `freeze_trials_shuffled` exists
   for C1 but is `#[cfg(test)]` only and has no SHD analogue. A DFA arm scoring
   0.23 on shuffled labels would be very informative.
3. **Per-arm learning-rate sweeps on SHD.** Scale parity at init is fixed;
   whether `lr = 0.02` is right for *either* arm is untested.
4. **Cell-specific inhibitory projections.** Required before
   `ei-inhibition-sweep` C3 can pass. Currently an architectural limitation, now
   documented rather than papered over.
5. **Real Metal dispatch.** Scaffolded with a checklist; flip
   `METAL_GPU_DISPATCH_IMPLEMENTED` when the encoder bodies land.
