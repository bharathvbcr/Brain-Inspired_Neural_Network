**Scope:** all 15 reports in the run directory + the code paths that produced them

## Part 2 — Code defects (severity-ordered)

### 2.1 CRITICAL — `c1_enhanced.rs`: the accuracy is a constant predictor with no input

`binn-lab/experiments/c1_enhanced.rs:93-108`

```rust
for sample in test_samples {
    engine.reset_state();                      // wipes state
    let scores = (0..hidden).map(|id| {        // reads engine cells...
        let c = engine.cell(id);
        (id, c.v + c.dendritic_coincidence_score())
    });
    let winners = soft_k_wta(&scores, 8, 0.1, 9999);
    let predicted = !winners.is_empty();       // <-- sample-independent
    if predicted == (sample.label != Some(0)) { correct += 1; }
}
```

`sample` is never fed into the engine. `engine.reset_state()` is called first, so the
membrane values read are identical on every iteration. `predicted` is therefore a
**constant boolean**, and "accuracy = 0.8500" is simply the positive-class fraction of
the test set. The training loop above it (lines 56-90) performs **zero weight updates** —
it prints an accuracy that only changes because `temp` changes the WTA sampling.

`c1_enhanced.md` reports no learning result.

### 2.2 CRITICAL — `multi_area_scaling.rs`: same defect, plus a per-arm dataset confound

`binn-lab/experiments/multi_area_scaling.rs:129-149`

```rust
let input_winners: Vec<CellId> = (0..k as CellId).collect();  // fixed constant
let mut prev_winners = input_winners;
for i in 0..(n_areas - 1) { prev_winners = net.fused_inter_area_step(...); }
let predicted = !prev_winners.is_empty();                     // sample-independent
```

The network input is the literal set `{0,1,2,3}` for every sample. The "online feedback
update" (line 107-122) passes `dummy_pre = vec![1.0; n]`, `dummy_post = vec![1.0; n]` —
also sample-independent. No information from the data ever enters the network.

Compounding it: each M uses a **different** synthetic stream seed
(`SynthConfig::toy(100 + n_areas)`) and a **20-sample** test split. So 0.75 / 0.40 / 0.90
are 15/20, 8/20, 18/20 — the positive-class fractions of three *different* tiny datasets.
95% CI half-widths are ±0.19, ±0.22, ±0.13; the three points are mutually
indistinguishable even if the measurement were meaningful. Test accuracy (0.90) exceeding
train accuracy (0.7333) at M=8 is the tell.

### 2.3 CRITICAL — the Metal GPU benchmark never touches the GPU

`binn-core/src/metal_backend.rs:50-68`

```rust
pub fn spmv(&self, csr: &Csr, weights: &[f32], x: &[f32], y: &mut [f32]) {
    ...
    // High-performance CPU SIMD / Rayon execution path
    y.par_iter_mut().enumerate().for_each(|(r, y_val)| { ... });
}
```

`self.config.use_gpu` is **never read**. The `use_gpu: false` and `use_gpu: true`
backends in `c1_enhanced.rs:147-155` and `multi_area_scaling.rs` run byte-identical code.
That is the entire explanation for the 0.94x–1.04x "speedups" in both reports — you are
benchmarking rayon against rayon and reading the noise.

The real Metal path exists but is a stub:
`metal_backend.rs:205` → `unimplemented!("Metal dispatch not yet fully implemented")`.
It is behind `#[cfg(feature = "gpu")]` and would panic if reached.

Every GPU/throughput number in this run should be withdrawn.

### 2.5 CRITICAL — SHD e-prop "ceiling" is crippled by a ~57× effective-LR deficit

Both arms share `lr = 0.02` and the same `ShdArch`. The hidden-layer modulator differs:

```rust
// ShdDfa::step        (shd_eprop_baseline.rs:265-269)
m  = Σ_k  feedback[i,k] · (−delta[k])        // feedback ~ U[−1, 1]
// ShdEpropCeiling::step (shd_eprop_baseline.rs:474-477)
di = Σ_k  wout[k,i]     ·   delta[k]          // wout ~ U[−1,1] · 0.2/√h
```

With `h = 128`: `sd(B) = 0.577`, `sd(wout) = 0.0102` → **56.6×** ratio in modulator
magnitude, hence in effective hidden-layer step size. The "ceiling" is not undertuned by
a little; it is running at roughly 2% of the treatment's learning rate.

This is the sole reason the ceiling (0.092–0.126) sits *below* the treatment (0.209–0.239).
**A ceiling below the thing it is supposed to bound is a broken ceiling**, and it
invalidates every DFA-vs-local-rule reading on SHD in this run. Fix: normalise `B` to
match `‖wout‖` (or per-arm LR sweep) before any comparison is reported.

Secondary: `ShdEpropCeiling::step` computes `di` from `wout` *after* the readout update in
the same step, so the hidden signal uses a one-step-stale-in-the-wrong-direction transport
matrix. Minor next to the scale bug, but wrong.

### 2.6 MAJOR — SHD width scaling shows no scaling, and the report doesn't say so

| N | mean | sd | 95% CI | wall |
|---|---|---|---|---|
| 128 | 0.2336 | 0.0473 | [0.192, 0.275] | 71 min |
| 256 | 0.2088 | 0.0366 | [0.177, 0.241] | 131 min |
| 512 | 0.2392 | 0.0269 | [0.216, 0.263] | 264 min |

512 vs 128: Δ = **+0.0056**, SE = 0.0243, t = **0.23**. A 4× width increase and a 3.7×
compute increase buy statistically nothing, and the trend is non-monotonic. That *is* a
result — the bottleneck is the credit rule, not hidden capacity — but it is the opposite
of "width scaling," and no report states it.

Also: the `--shd-hidden 512` run's Reproduce block omits the flag (`c1_shd_h512.md`
copies the h128 command verbatim). The h128 report is non-reproducible from its own
instructions.

### 2.7 MAJOR — no depth-matched control in the depth-scaling suite

`deep_snn_scaling.rs:118` compares 2L/3L/4L learned-FB against a **1-hidden-layer**
`MatchedGradient` ceiling. There is no 2L/3L/4L BPTT arm. So the observed collapse
(1.00 → 0.45) cannot be attributed to feedback alignment — an equally consistent
explanation is that deep nets on this task are hard to optimise at `eta = 0.05`,
`epochs = 80`, or that depth is simply useless here (see 2.8). The experiment as built
cannot distinguish these.

### 2.8 MAJOR — the matched-arch task is a 2-input toy; 1.0000 accuracy means nothing

`freeze_trials` → `CoincidenceTask` (`binn-data/src/datasets.rs:75-145`):
`n_features = 2`, `n_classes = 2`, `sequence_len = 8`, `difficulty = 0.05`. So
`GradientExample = ([f32; 8], [f32; 8], f32)` — **N_IN = 2**.

Consequences:

- Feeding a 2-dimensional, near-noiseless input into a 256⁴ network and calling the
  result "deep SNN scaling" is not informative. The task has no depth structure to find.
- `1.0000 ± 0.0000` across 20 seeds, *exceeding* the BPTT reference (0.9895), is the
  standard signature of a saturated toy task. It is being read as "FA matches backprop";
  it actually means the task is too easy to separate the arms.
- Gap-closed values of **1.0244** and **1.0155** (`live_transfer_rescue.md`,
  `track_b_rescue.md`) are >100% for exactly this reason. The C1 harness clamps
  gap-closed to `[0,1]`; these two rescue harnesses **don't**. Inconsistent clamping
  across harnesses in the same run directory.
- `datasets.rs:123`: `let positive = (trial_id & 1) == 0;` — labels **strictly alternate**
  by trial ordinal. It gives exact 50/50 balance, but it also means any code path that
  consumes trials in order has a trivially predictable label stream. The matched arms
  shuffle per epoch so they're safe; this is a landmine for anything that doesn't.

### 2.9 MAJOR — `ei_inhibition_sweep` and `multi_channel_neuromod` are not experiments

**`ei_inhibition_sweep.rs:65-93`** drives the interneuron area with i.i.d. uniform noise
(`rng.next_f32() * 2.0`) rather than network activity, for 50 steps, then reports
`smoothness = 1/(1 + var)`. With i.i.d. input the variance of pooled inhibition is fixed
by the pooling arithmetic, so "smoothness" is a deterministic function of `w_ie` and
`n_inh` — no dynamics, no competition, no task, no k-WTA. The conclusion "provides stable,
continuous soft-WTA competition" is not tested by anything in the file.

**`multi_channel_neuromod.rs:48-58`** is two calls to `compute_signal` with hand-picked
scalars, one seed, no dataset, no control, no metric beyond the mean of the returned
vector. There is no hypothesis and nothing that could come out false.

Both should be reclassified as unit tests / sanity prints, not suite results.

### 2.10 MODERATE — REINFORCE readout arms sit at chance on SHD

`SHD_BROADCAST_PM1` = 0.0528–0.0548 and `SHD_RL_REINFORCE_FB` = 0.0504–0.0532 against a
0.05 chance line, at every width. A 20-way softmax readout over fixed rate features should
clear chance comfortably; sitting *exactly* on it across 15 seed-runs is a harness smell,
not a finding about local rules. The two arms that clear chance (DFA, e-prop) are exactly
the two that apply the true CE gradient `δ = p − onehot` to `wout`. Before publishing
"REINFORCE fails on SHD," check whether the REINFORCE readout is learning at all
(log `‖Δwout‖` per epoch; try a per-arm LR sweep).

## Part 3 — What actually survives

Three things, all negative or descriptive:

1. **DFA on SHD clears chance by ~4×** (0.21–0.24 vs 0.05) under capped 2000/500 subsets,
   5 seeds, with tight CIs. Real, and the caps are honestly disclosed. Says nothing about
   any ceiling until 2.5 is fixed.
2. **Hidden width is not the bottleneck** for the local rules on SHD (§2.6).
3. **The matched-schedule / live-engine gap is real and large.** `c1_rfb_learned.md`:
   matched dense-LIF reaches 1.0000, live k-WTA event-driven reaches 0.5188 on the same
   task. That gap is the most interesting number in the whole run and is the one the
   summary buries. Report verdict is FAIL/U-NEG, and the preregistration says the program
   stops at G2.

Everything else is either instrumented to pass, measuring class balance, or comparing
against a broken ceiling.

## Part 4 — Fixes, in priority order

**Stop-the-line (before anything is claimed):**

1. `metal_backend.rs:50` — make `spmv` branch on `self.config.use_gpu`, or delete the
   flag and rename the struct. Withdraw all GPU numbers from `c1_enhanced.md` and
   `multi_area_scaling.md`.
2. `c1_enhanced.rs` and `multi_area_scaling.rs` — feed `sample` into the engine and derive
   `predicted` from a readout over post-stimulus state. Until then, delete the accuracy
   rows.
3. Delete all hardcoded `PASS` literals (§2.4). Add a workspace lint or a test that greps
   report format strings for verdict literals not backed by a comparison.
4. `shd_eprop_baseline.rs` — normalise `feedback` to `‖wout‖` at init, or run a per-arm LR
   sweep, and re-run h128/h256/h512. Re-derive every ceiling claim.

**Correctness:**

5. Add depth-matched gradient ceilings (2L/3L/4L BPTT) to `deep_snn_scaling.rs`.
6. Move the matched-arch suites off `CoincidenceTask` (N_IN=2) onto something with real
   input dimensionality — the SHD path already exists. A ceiling that loses to FA is a
   signal the task is exhausted.
7. Unify gap-closed clamping across `runner.rs`, `track_b_rescue.rs`,
   `live_transfer_rescue.rs`. Report >1.0 as a harness warning, not a result.
8. Raise `multi_area_scaling` test splits well above 20 and hold the dataset seed fixed
   across M.

**Hygiene:**

9. Add an assertion that `INVALID_HARNESS` runs cannot be cited as positive evidence
   anywhere downstream — two of them were, in this run's own summary.
10. Fix the `--shd-hidden` flag in the h128/h512 Reproduce blocks.
11. Add a shuffled-label control to the SHD arms. `freeze_trials_shuffled` already exists
    for C1 but is `#[cfg(test)]` only and has no SHD analogue. A DFA arm that scores 0.23
    on shuffled labels would explain a lot.
12. Enable `--features plots`. Every raster and weight plot in three 50KB reports is
    `Skipped("plots feature disabled")`.
